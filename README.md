# Uplift Modeling: кому отправлять промо-рассылку

Проект по uplift-моделированию на данных программы лояльности X5 RetailHero. Задача: определить клиентов, на которых SMS-рассылка **реально повышает** вероятность покупки, а не тех, кто купил бы и без неё. Это отличается от обычной классификации: нужно предсказывать не «купит ли клиент», а «насколько рассылка изменит вероятность покупки».

## Результат в двух словах
Рассылка в среднем повышает конверсию на 3,3 п.п. Если отправлять её только 30% клиентов с наибольшим предсказанным uplift, прирост конверсии на получателя составляет около 6,7 п.п. против 2,9 п.п. при случайном выборе (в 2,3 раза выше). Все модели лучше случайного ранжирования; лучшая по Qini AUC — S-learner, но три лучшие модели статистически различаются слабо.

## Данные
X5 RetailHero uplift (`sklift.datasets.fetch_x5`, скачивается автоматически, около 600 МБ): 200 039 клиентов, из них 50% получили рассылку (treatment), конверсия в целевое действие 62%. Есть данные о клиентах и история покупок до рассылки.

Разбиение: 70% обучение (140 027 клиентов) и 30% тест (60 012 клиентов), стратификация по комбинации «рассылка × цель».

## Признаки
- **Профиль клиента:** возраст (выбросы заменены на пропуски), пол, давность выпуска карты, время от выпуска карты до первого использования баллов, признак «использовал баллы».
- **Агрегаты по покупкам:** число чеков, общая сумма, средний и максимальный чек, начисленные и потраченные баллы, число магазинов, давность последней покупки, длительность активности, число позиций и уникальных товаров.

## Модели
Базовый алгоритм везде LightGBM, подходы из библиотеки scikit-uplift:
- **SoloModel (S-learner):** одна модель, рассылка — один из признаков;
- **ClassTransformation:** преобразование целевой переменной, одна модель на преобразованной задаче;
- **TwoModels (T-learner):** две модели на группах с рассылкой и без неё, в вариантах `vanilla` и `ddr_control`;
- **Random:** случайное ранжирование клиентов (контроль).

## Метрики
- **Qini AUC / Uplift AUC:** площадь под кривой накопленного прироста при ранжировании по предсказанному uplift. Чем выше, тем лучше; у случайного ранжирования около нуля.
- **uplift@k:** разница конверсий между группами с рассылкой и без неё среди k% клиентов с наибольшим предсказанным uplift.
- **Bootstrap-доверительные интервалы** Qini AUC (200 выборок тестового набора) — чтобы понимать, не случайна ли разница между моделями.

## Результаты (test, 60 012 клиентов)
Средний эффект рассылки (ATE): **+3,3 п.п.** конверсии.

| Модель | uplift@10% | uplift@30% | Qini AUC | Uplift AUC |
|:--|--:|--:|--:|--:|
| SoloModel (S-learner) | 0,110 | 0,0665 | **0,0153** | **0,0231** |
| ClassTransformation | **0,1247** | 0,0641 | 0,0139 | 0,0202 |
| TwoModels (ddr_control) | 0,098 | 0,0574 | 0,0107 | 0,0161 |
| TwoModels (vanilla) | 0,081 | 0,0516 | 0,0074 | 0,0111 |
| Random (контроль) | 0,0197 | 0,0285 | -0,0022 | -0,0035 |

Доверительные интервалы Qini AUC (95%):

| Модель | Qini AUC | Нижняя граница | Верхняя граница |
|:--|--:|--:|--:|
| SoloModel (S-learner) | 0,0153 | 0,0095 | 0,0207 |
| ClassTransformation | 0,0139 | 0,0083 | 0,0187 |
| TwoModels (ddr_control) | 0,0107 | 0,0056 | 0,0155 |
| TwoModels (vanilla) | 0,0074 | 0,0020 | 0,0133 |
| Random (контроль) | -0,0022 | -0,0074 | 0,0029 |

## Выводы
- **Все модели полезны.** Интервалы S-learner, ClassTransformation и T-learner (ddr_control) целиком выше нуля и не пересекаются с интервалом случайного ранжирования. У T-learner (vanilla) нижняя граница (0,0020) чуть ниже верхней границы случайного ранжирования (0,0029), то есть интервалы слегка пересекаются: это самая слабая модель, и её превосходство над случайным выбором менее убедительно.
- **Ранжирование моделей не окончательное.** Доверительные интервалы S-learner и ClassTransformation сильно пересекаются, поэтому различие между ними нельзя считать надёжным. Корректная формулировка: «модели сопоставимы, S-learner немного лучше по Qini AUC».
- **Выбор модели зависит от охвата.** На верхних 10% клиентов лучше ClassTransformation (12,5 п.п.), при охвате 30% — S-learner (6,7 п.п.).
- **Практический смысл.** Адресная рассылка на 30% клиентов даёт прирост на получателя в 2,3 раза выше, чем случайная рассылка, при том же числе сообщений на этой доле базы.
- **Экономический расчёт** (прибыль в зависимости от доли клиентов, оптимальная доля) выполняется скриптом с параметрами `--value` и `--cost` и сохраняется в `results.md` и `profit_curve.png`. Параметры по умолчанию иллюстративные, для реального решения нужны значения компании.

## Как запустить
```bash
pip install -r requirements.txt
python uplift.py                                # реальные данные
python uplift.py --value 1000 --cost 5          # с вашими параметрами прибыли и стоимости
python uplift.py --synthetic                    # быстрая проверка кода на синтетике
```

## Ограничения и возможные улучшения
- Один train/test-сплит: интервалы получены только bootstrap-ом тестовой выборки, без повторного обучения моделей. Следующий шаг — кросс-валидация.
- Гиперпараметры LightGBM не подбирались.
- Расчёт прибыли упрощённый: фиксированная прибыль с покупки и стоимость сообщения.
- Не использованы другие uplift-подходы (деревья uplift, мета-learner'ы на основе R/X-learner) и дополнительные признаки по категориям товаров.
